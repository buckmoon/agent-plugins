# mock-notes.js の項目と関数

## MockNotes.init(options)

モックの最初の描画の後で1回呼ぶ。もう一度呼ぶと、前の注記を消して作り直す。

| 項目 | 要否 | 内容 |
|---|---|---|
| `key` | 必須 | ブラウザの保存領域（localStorage）に使う名前。モックごとに変える。動かした位置・隠した注記・表示の切り替えを覚える |
| `notes` | 必須 | 注記の配列。並び順が番号（#1, #2…）になる |
| `baseline` | 推奨 | 「修正済み」が何からの変更か（例：`v1（11/1 の版）`）。凡例の説明と書き出しに出る |
| `mount` | 任意 | 道具の帯を置く要素（セレクタか要素）。省くと画面の左下に浮かせる。モックの描き直しで消える場所に置いたときは、次の配置で置き直す |

## 注記の項目

| 項目 | 対象の種類 | 内容 |
|---|---|---|
| `id` | すべて | 版をまたいで変えない名前。重複すると `init` が止まる |
| `kind` | すべて | `fixed`（修正済み）・`conflict`（要解決）・`assumption`（要確認） |
| `screen` | すべて | 一覧に出す画面名（例：`申請の設定 > 承認ルール`） |
| `target` | すべて | 指す要素の CSS セレクタ。1つの要素にだけ一致させる |
| `where` | すべて | 場所。画面を見ている人が探せる言葉 |
| `what` | fixed・assumption | fixed は何をどう変えたか、assumption は仮に置いた内容 |
| `from` | 任意 | 出典（例：`FB-003 青木さん`） |
| `title` | conflict | 何についての対立か |
| `opinions` | conflict | `[{ who, says }]`。人ごとの意見 |
| `ask` | conflict・assumption | conflict は決めてほしいこと、assumption は確かめたいこと |
| `path` | すべて | 開き方の手順（下表）。空なら、対象が見えている画面でだけ開ける |

文字はすべてそのまま表示する（HTML として解釈しない）。

## path の手順

| 書き方 | 動き |
|---|---|
| `{ click: 'セレクタ', say: '…' }` | その要素を押す |
| `{ select: 'セレクタ', value: '…', say: '…' }` | 選択肢を選び、`input` と `change` を起こす |
| `{ go: '#/settings', say: '…' }` | URL のハッシュを変える。クリックで行けない画面にだけ使う |
| `optional: true` | その手順の要素がなければ飛ばす（ログイン画面など、状態によって出る物） |

`say` を省くと、要素の文字から「「〇〇」を押す」を作る。手順ごとに、要素が現れるまで最大1.5秒待つ。

一覧から注記を押したとき、対象がもう見えていれば手順を飛ばす。見えていなければ、カーソルを動かしながら手順を順にたどる。「スキップしてすぐ開く」を押すと、残りの手順を動きなしでたどる。

## 関数

| 関数 | 内容 |
|---|---|
| `MockNotes.refresh()` | 配置をすぐやり直す。描き直しは自動で追うので、普段は要らない |
| `MockNotes.open(id)` | その注記の開き方を再生する |
| `await MockNotes.verify()` | 全注記の `path` を順にたどり、`[{ id, no, ok, reason }]` を返す。手順の要素がない・対象がない・対象のセレクタが複数に一致する、を見つける。画面を実際に操作するので、データを書き換える手順があれば初期化してから実行する |
| `MockNotes.exportText()` | 注記を文字で書き出す（番号・種類・画面・場所・中身・出典・id）。道具の帯の「文字で書き出す」と同じ |
| `MockNotes.lastTour` | 直前の再生で表示した手順の文（テスト用） |
| `MockNotes.destroy()` | 注記を消す |

## 置き方の決まり

- リーフの左下を、対象の中身（文字など）の右上に合わせる。ボタン・入力欄・画像は、要素の枠の右上に合わせる。
- カードの既定の位置は、画面の右の余白。そこが対象に重なるときは対象の下に置く。対象がダイアログ（`[role="dialog"]`・`dialog`・`.modal`）の中にあるときは、ダイアログの横に置く。カード同士・ほかのリーフ・ほかの対象には重ねない。幅720px未満では対象の下に置く。
- ダイアログが開いている間は、そのダイアログの中の注記だけを出す。
- カードが、足した列の値などモックの中身に重なることがある。読む人はドラッグか×で逃がせる。カードの位置のためにモックの配置を変えない。
- ドラッグした位置は、リーフからの相対で覚える。注記の中身が変わると、覚えた位置と隠した状態は引き継がない。
- 対象が画面にないとき（別の画面・閉じたダイアログ・隠れたタブ）は、リーフもカードも出さず、一覧にだけ出す。
- 注記の部品は `position: fixed` の層（`.mn-root`）に描く。部品の中のクリックは外へ伝えない。部品の要素の印は `data-mn` で、モックの `data-act` などとはぶつからない。
