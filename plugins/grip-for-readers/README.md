# Grip for Readers

Grip for Readers（`grip-for-readers`）は、AIが書いた文章を、読み手が読み終えたときに、次に何をすればよいかが分かる形にするための、Claude Code と Codex のプラグインである。この README では、何を目指しているか、どんな仮説の上に立っているか、使うときに何に注意すべきかを説明する。入れ方はリポジトリの [README](../../README.md) にある。

## 目指す状態

読み手が読み終えたとき、次に自分が何をすればよいかが分かっていること。ほかの資料を調べたり、書き手に聞き返したりしなくても分かる状態を指す。具体的には、次の二つが満たされている。

- 冒頭の数行で、読み手は自分が何をすればよいか（返事をする、選ぶ、レビューする、知っておくだけ、など）が分かる
- 読み手が見ていない語（作業中に読んだファイル名、途中で付けた呼び名、issue 番号など）が、説明なしに残っていない

AIの報告は、書いたAIには分かりやすくても、読み手には読みにくいことが多い。AIは作業中に多くのファイルやツールの出力を見ていて、読み手が見ていない語や出来事を、説明なしに使ってしまうからである。Grip for Readers は、この食い違いを、文章が読み手に届く前に埋めることを狙う。

## 仕組み

二つの部品からなる。

- **スキル**（[skills/grip-for-readers/](skills/grip-for-readers/SKILL.md)）：書き始める前に、読み手がこれまでに何を見てきたか（手持ち）と、読み終えたときに何をしてほしいか（次の行動）を決めさせる。そのうえで、文章の種類によって扱いを分ける。
  - **短いやり取り**（数行で済む返事や、判断の要らない返事）：下書きを書かず、そのまま返す。試し読みは動かないので、待ち時間もない
  - **時間のかかった作業のあとの報告**（作業をやり終えた、調査した、道具を10回以上使った、判断や操作を頼む）、**第三者に渡す文面**（PR本文・Slack・メールなど）、**ファイルとして残す文書**：いったん下書きファイルに書かせる。試し読みが動くのはこの下書きが400字以上のときだけで、1回に4〜15秒ほど待たされる
- **試し読みフック**（[hooks/](hooks/)）：下書きの書き込みと、GitHub の MCP の道具での投稿の直前に、読み手が見たものだけを渡した別のAI（試し読み役）に文章を読ませる。読み手が何をすればよいか分からない、または引っかかる文があれば、書き込みや投稿を止め、質問を書き手のAIに返して書き直させる。

下書きは、AIがスキルの指示に従って、一時フォルダ（環境変数 `TMPDIR` の場所。空なら `/tmp`）の下の `grip-for-readers-drafts/` に作る。利用者が名前を付ける必要はない。読み手の種類は、AIが付けるファイル名の先頭で決まる。先頭なし（例：`20260925-1430.md`）は依頼者（AIに作業を頼んでいる人）向けで、ほかに `github-`・`slack-`・`email-`・`doc-`（後日文書を開く人）がある（例：`slack-20260925-1430.md`）。

## 依拠している仮説

Grip for Readers は、次の仮説が成り立つことを前提にしている。確かさの欄は、どこまで確かめたかを示す。数字は作者の手元の小さな実験（作業報告15本・108文、書き直しの比較は6本）から出たもので、判定と評価の多くはAIが行った。表の「重い文」は、読み手が引っかかる、読み直す、または読んでも次に何をすればよいか分からない文を指す。どの文が重いかは、実験の前に、別のAIが読み手の立場で判定した。

| 仮説 | 根拠 | 確かさ |
|---|---|---|
| 作業の文脈を多く持つ書き手ほど、読み手の知らない語に気づかず、伝わり方を過大評価する | Wu & Keysar 2007、Keysar & Henly 2002 | 先行研究（要約で確認） |
| 読み手が見たものは、依頼者の発言とAIの本文で近似できる。ツールの入出力や、AIが作業中に読んだファイルは、読み手は見ていない | 設計上の仮定 | 未検証 |
| 読み手が見たものだけを渡された別のAIは、読み手が引っかかる文を拾える | 実験で、重い文の52〜60%を拾い、指摘の73〜78%が当たった。読み手がそれまでに見た記録に出てこない語を機械で拾う方法では、拾えたのが31%、当たったのが65%だった | 小実験（AIの判定） |
| 直すのは、作業の文脈を持つ元の書き手でなければならない | 実験で、文脈を持たない別のAIに書き直させると、短くならず、用件を取り違えた。読み手の反応を受けた書き手は改訂できる（Traxler & Gernsbacher 1993、Damen ほか 2021） | 小実験と先行研究 |
| 冒頭に次の行動を書くと、読み手は何をすればよいかを確信できる | 次の一手の確信度（5段階）が、AIの評価で2.7〜2.8から4.3〜4.5に、人間1人の評価で2.8から4.2に上がった | 小実験（人間は1人・6本） |
| 数行で済む、判断の要らない返事には手順は要らない。短さそのものが「深く読まなくてよい」という合図になる | 人間の読み比べで、短い元の報告が1位に選ばれたことがあった | 観察（1人） |
| 止めるのは1回で足り、それ以上は止めすぎになる | 過去の報告3本に当てると3本とも止める判定になり、重要でない質問も混じった | 観察（3本） |

経緯と実験の詳細は [docs/design.md](../../docs/design.md) にある。

## 注意事項

**試し読みが見るのは読みやすさで、内容の正しさではない。** 試し読み役は、読み手が引っかかるかどうかを判定する。事実の誤りや判断の誤りを見つける仕組みではない。

**試し読みはAIの判定なので、外れることがある。** 重い文の見逃しも、重要でない質問も起きる。止めるのは、同じ依頼の中で読み手ごとに1回だけで、書き直した版は止めない。「同じ依頼」は、依頼者の発言1回ごとに区切る。依頼者が次のメッセージを送ると、また1回止められるようになる。答えられない質問は「まだ分かっていないこと」として本文に残させる。

**利用量と待ち時間がかかる。** 短いやり取りでは試し読みは動かず、待ち時間もかからない。試し読み役は、400字以上の下書きや投稿のたびに、利用者のAI（`claude -p` または `codex exec`）で1回動く。1回に4〜15秒ほど書き込みが待たされる。呼び出しに失敗したときは、止めずに通す。

**文章の全文を送り、手元に残す。** 下書きの全文（依頼者向けなら会話の記録も）を、利用者がふだん使っているAIの提供元に送る。試し読みした文章の全文と判定は、`~/.claude/grip-for-readers/`（Codex では `~/.codex/grip-for-readers/`）の記録に残る。詳しくは [docs/privacy-and-cost.md](../../docs/privacy-and-cost.md) にある。

**試し読みしない経路がある。**

- `gh` コマンドなど、シェルから GitHub に投稿したとき
- Codex で、既存の下書きを書き換えたとき。フックに全文が渡らないため
- AIがスキルに従わず、下書きを書かずに答えたとき。作者の手元の記録では、依頼者への長い報告34件のうち、下書きを通ったのは2件だった。確実に通したいときは、「grip-for-readers スキルの手順で書いて」と頼む

**Codex では、フックを信頼するまで試し読みが動かない。** 入れたあと、対話モードの `/hooks` で grip-for-readers のフック2件を信頼する必要がある。

**日本語話者向けである。** スキルも試し読み役への指示も日本語で書いてあり、試し読み役は日本語の読み手として判定する。

**止めたいとき**は、起動前に環境変数 `GRIP_FOR_READERS=0` を設定する。
