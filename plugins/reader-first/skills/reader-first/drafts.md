# 下書きと試し読みの手順

1. **下書きを書く。** 本文の全体を、一時フォルダの下の `reader-first-drafts/` に、新しいファイルとして書く。一時フォルダは環境変数 `TMPDIR` の値で、空なら `/tmp` を使う。パスは絶対パスにする（分からなければ `echo "${TMPDIR:-/tmp}"` で確かめる。例：`/var/folders/ab/xyz/T/reader-first-drafts/slack-20260925-1430.md`）。ファイル名の先頭には、[readers.md](readers.md) の接頭辞を付ける。依頼者向けは接頭辞なしで `20260925-1430.md` とする。この時点では、チャットにも送り先にもまだ何も出さない。
2. **試し読みを待つ。** フックが、読み手の立場の別のAIに下書きを読ませる。引っかかる点があると書き込みが止められ、質問が返ってくる。
3. **止められたら直す。** 作業の文脈を持つ自分が質問に答える形で直し、同じ接頭辞の新しいファイル名でもう一度書く。書き込んだ下書きを後から書き換えても、試し読みはされない。止められるのは、同じ依頼の中で読み手ごとに1回だけである。
4. **書き込みが通ったら、下書きと同じ内容を本来の場所に出す。** 下書きや試し読みがあったことには触れない。
   - 依頼者向け：チャットに出す
   - Slack・メール：チャットに、そのまま貼れる形（コードブロックなど）で示すか、依頼者に頼まれていれば送る
   - issue・PR：投稿する。GitHub の MCP の道具で投稿するときは、投稿の直前にもフックが読む。`gh` コマンドなどシェルから投稿するときはフックが読まないので、下書きを必ず通す
   - 文書：本来の保存先に同じ内容で書く

読み手に選んでほしい選択肢や質問は、下書きの本文の中に書く。選択肢を並べて答えを求める道具だけに置いた選択肢は、試し読みのAIには見えない。
