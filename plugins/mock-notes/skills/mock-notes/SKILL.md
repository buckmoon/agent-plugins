# モックに注記を浮かべる

`mock-notes.js` をモックに貼ると、画面の上に注記が浮かぶ。対象の右肩にリーフ（しずく形の印）が付き、矢印で、場所と変更を書いたカードにつながる。道具の帯からは、注記の一覧、開き方の再生（左メニュー→タブ→…とカーソルが動く）、文字での書き出しが使える。どのモックでも同じ見た目と操作なので、読む人は一度覚えればよい。注記の中身は、モックの最後に置く `notes` の配列に書く。

見本：`example.html`。項目と関数の詳細：`reference.md`。

## 注記は3種類

| kind | 画面の表示 | 使うとき | 書く項目 |
|---|---|---|---|
| `fixed` | 修正済み（緑） | 基準の版から変えた箇所 | `where` 場所、`what` 何をどう変えたか、`from` 出典 |
| `conflict` | 要解決（赤） | 意見が分かれている点。作り手が決めてはいけない判断 | `title`、`where`、`opinions` に人ごとの意見、`ask` 決めてほしいこと |
| `assumption` | 要確認（橙） | 指示がないまま作り手が足した物、解釈で埋めた中身 | `where`、`what` 仮に置いた内容、`ask` 確かめたいこと、`from` |

どの注記にも `id`（版をまたいで変えない名前）、`screen`（一覧に出す画面名）、`target`（指す要素の CSS セレクタ）、`path`（そこまでの開き方）を書く。

## 注記の書き方

- **変えた箇所ごとに注記を付ける。** 頼まれた変更でも、中身を推測で埋めた部分（書式、列、初期値など）があれば、`fixed` とは別に、その部分を指す `assumption` を付ける。`target` は変えた要素そのものを指す。列を足したら列見出し、欄を足したらその欄のラベル、ボタンならボタン。表全体や枠を指すと、矢印がどこを変えたかを示さない。`target` は1つの要素にだけ一致させる。一致する印がなければ、モックの要素に `id` を足す。
- **`where` は画面を見ている人が探せる言葉で、`what` は何をどう変えたかを一文で書く。** 「対応しました」では足りない。
- **`from` には、フィードバックの番号と発言者を書く**（例：`FB-003 青木さん`）。
- **意見が分かれたら `conflict` に並べる。** どちらかに寄せず、各人の意見を本人の言葉に近い形で `opinions` に入れる。決める人が示されていなければ、決める人は書かず、`ask` に何を決めるかだけを書く。モックは両案を選べる形にするか、前の版のままにする。
- **フィードバックにない物を足したら、必ず `assumption` にする。** 解釈で中身を埋めたとき（形式、列、文字コード、初期値など）も同じ。注記なしで入れない。
- **`notes` は、決めてほしい順（`conflict` → `assumption` → `fixed`）に並べる。** 番号（#1, #2…）はこの並び順になるので、読む人は若い番号から答えればよい。
- **`path` は、どの画面にいても同じ結果になる操作から始める**（左メニューのリンクなど）。`say` は画面の言葉で「「〇〇」を押す」と書く。
- **モックそのものの見た目は変えない。** 札や背景色で変更点を示すのは注記の仕事で、モックの UI に混ぜない。

## フィードバックを受けて次の版を作る手順

1. **フィードバックを項目に分けて番号を振る**（FB-001…）。言い換えで意味を足さない。
2. **基準（`baseline`）を決める。** 指示がなければ「前の版」にする。
   - 前の版が基準：前の版の `fixed` は消す。`conflict` と `assumption` は答えが出るまで残す。
   - 最初の版が基準：前の版の `fixed` も残して積み上げる。
   - 答えが出た `conflict` と `assumption` は `fixed` に変え、`what` に決まった内容を、`from` に答えの出典を書く。`id` は変えない。
3. **モックを直し、変えた箇所ごとに注記を書く。**
4. **検証する。** ブラウザで `await MockNotes.verify()` を実行し、全件が `ok: true` になるまで直す。ヘッドレスブラウザが使えるなら自分で実行し、各画面のスクリーンショットで、矢印が変えた要素を指していることを目で確かめる。使えないなら、利用者に「注記の一覧から全件を押して、開けるか見てください」と頼む。
5. **報告する。** 書き出し（`MockNotes.exportText()` の文字、または同じ形）を、決めてほしい `conflict` と `assumption` から順に並べて渡す。

## 返事を受けて直すとき

読む人は、道具の帯の「文字で書き出す」で注記を Slack や AI に貼り、「#3 は森さん案で」「csv-format は Shift_JIS で」のように返す。番号は並び順で版ごとに変わりうるので、返事の番号は、その版の書き出しで `id` に読み替える。読み替えたら、手順2のとおり種類を変える。

## 組み込み方

- 1ファイルで配るときは、`mock-notes.js` の中身をモックの `<script>` にそのまま貼る。外部への通信はしないので、Slack の HTML 表示の中でも動く。
- モックの最初の描画の後で、`MockNotes.init({ key, baseline, notes })` を1回呼ぶ。描き直しは自動で追う。
- モックのクリック処理が、注記の部品（`.mn-root`）の中のクリックに反応しないことを確かめる。
- Slack の HTML 表示の中では、ダウンロード・別ウィンドウ・クリップボードが効かない。モックでこれらを見せる機能（CSV の書き出しなど）は、押したら中身を画面に出す形にする。注記の「文字で書き出す」は、クリップボードが使えないと、選んでコピーできる欄を出す。

## よくある間違い

| 間違い | 直し方 |
|---|---|
| 矢印が表や枠の全体を指していて、どこを変えたか分からない | `target` を変えた要素そのものにする |
| 2人の意見をまとめ、片方に寄せて作った | `conflict` で並べ、モックは両案を選べる形にする |
| 頼まれていない改善を黙って足した | `assumption` にして確かめてもらう |
| 決める人を推測で書いた | `ask` に何を決めるかだけを書く |
| 変更点を示すため、モックに札や色付きの枠を足した | 注記に任せ、モックの UI は変えない |
| 版ごとに独自の変更一覧パネルを作った | この部品を使う。読む人が見方を覚え直さずにすむ |
| `verify` を通さずに渡した | 渡す前に全件 `ok` を確かめる |
